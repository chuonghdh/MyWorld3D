# Brief: T-0029 (graphics-character)

- **Task id:** T-0029-ped-turn-start-stop-smoothing
- **Owner:** graphics-character
- **Reviewer:** reviewer (read-only subagent)
- **Goal:** smoother turns, starts and stops, for RENDER only. The simulation heading (`TURN_RATE` 7 rad/s in `walkers/constants.ts`), positions, routes and hashes do not change. Changed from the record's file list: do it ALL in the people layer so only one owner is involved: no change under `src/traffic/walkers/**` and no `trafficWalkers.ts` knob; knobs go in `src/config/tuning/trafficLife.ts` with the other people knobs.
- **Design (lead's, change with a reason):**
  - A new small pure state file under `src/traffic/people/` (e.g. `bodyMotion.ts`, pattern of `gaitPhase.ts`: typed arrays keyed by `ped.id % slots`, reset when another id takes the slot, dt from the shared `begin(time)`, clamped, zero on pause) holding per walker: smoothed render heading (critically damped or rate-limited chase of `ped.heading`, shortest angle, a knob `walkTurnRateRad` default about 3 rad/s, as the visible turn speed), the signed smoothed turn rate (rad/s), and a gait ramp 0..1 (rises over `walkRampS`, default 0.3 s, when the walker starts, falls when it stops; the walking flag is the same `walking` boolean used for `gaitPhase.step`).
  - Render heading: `writeInstance` gets the smoothed heading for people (positions unchanged). Things placed relative to the person must follow the SAME heading: umbrella offset (peopleMeshes.ts ~265), nothing for dogs (the leash hand position comes from the sim; leave it), check the film/audio/other consumers of heading from `PedestrianRender` (grep) are untouched since they read the sim value.
  - Head leads the body and the body leans into the turn: `aGait2.w` is free (reserved, written 0 since T-0034): send the signed turn rate (clamped, scaled to a unit range) there; in the shader (through `gaitMath.ts`, TS mirror + generated GLSL, same pattern as T-0028) add: torso and arms lean sideways about the forward axis by up to `walkLeanRad` (default about 0.06 rad), the head yaws ahead of the body by a few degrees in the turn direction (up to about 10 degrees, not a knob unless you want one), both zero when the turn rate is 0. Applies to WALKING people only so idle/chat/sit are bit-identical to now; check the depth material gets the same terms.
  - Gait ramp: multiply the walk amplitude `w.amp` (and the stride fit input if needed) by the ramp so legs and arms ease in and out instead of snapping when `walking` flips (at speed 0.02 threshold in peopleMeshes.ts `walking` computation). Keep the T-0034 planted-foot guard honest: the ramp lowers the amplitude only briefly during start and stop; document that the slip metric is for the steady state.
  - Knobs: `walkTurnRateRad` (3), `walkRampS` (0.3), `walkLeanRad` (0.06), each with a doc line, parity entry in `tests/tuningParity.test.ts`, row in `docs/TUNING.md` with the meaningful range (state any hidden gain). Update the `docs/TUNING.md` row for walker turn rate: the sim constant stays (`TURN_RATE`); note the visual rate is a separate knob.
  - Keep every file <= 350 lines (peopleMeshes.ts is 3xx: put new code in the new file and keep the hook-up to a few lines). Cache keys bump (far v8, near v10, depth v8).
- **Tests:** pure tests of the state file: render heading converges to the sim heading within a bounded time for turns up to pi, no overshoot, shortest-path wrap across +-pi, slot reuse resets, dt clamp and pause; ramp rises and falls monotonically in `walkRampS`; allocation-free (no new objects per call). Mirror test for the lean/yaw terms: zero at turn rate 0, bounded at the extremes, sign consistent between TS and GLSL (the sync check pattern from `peopleGaitMech.test.ts`). `tests/traffic.determinism.test.ts` must stay unchanged and pass.
